# Site v1 — launch checklist

This checklist tracks the first public release of the Marcelo Nicchio authority hub.

## 1. Editorial
- [ ] Cross-check dates, names, titles and role descriptions against the master biography.
- [ ] Distinguish public/external evidence from autobiographical material without overloading the prose.
- [ ] Keep Work in Progress projects explicitly labeled.
- [ ] Verify PT/EN parity while preserving natural language in each version.
- [ ] Review historical name variants and spelling in source-specific contexts.

## 2. Archive and rights
- [ ] Select only source assets that materially strengthen the public record.
- [ ] Do not publish IDs, signatures, private addresses, employment documents or full corporate records unnecessarily.
- [ ] Redact third-party personal data when a document excerpt is needed.
- [ ] Mark AI-generated historical reconstructions as reconstructions, never as original evidence.
- [ ] Check copyright/redistribution rights before uploading scans, decks or third-party images.

## 3. Search and entity signals
- [ ] Review titles and meta descriptions page by page.
- [ ] Validate canonical URLs and PT/EN hreflang pairs.
- [ ] Validate ProfilePage / Person structured data.
- [ ] Ensure ORCID and controlled external profiles link back to the official hub where possible.
- [ ] Move a thematic page from `noindex,follow` to `index,follow` only after editorial review.
- [ ] Add newly indexable pages to `sitemap.xml` at the same time.
- [ ] Keep one canonical work record when the same paper exists in multiple repositories.

## 4. Visual and accessibility
- [ ] Review desktop and mobile navigation.
- [ ] Test long titles and narrow screens.
- [ ] Check contrast and focus states.
- [ ] Add meaningful alt text when historical images are introduced.
- [ ] Confirm all primary actions and external source links work.
- [ ] Review favicon and future social-preview image.

## 5. Launch
- [ ] Final diff review in Pull Request #1.
- [ ] Confirm `main` is still the stable public source before merge.
- [ ] Merge only after the first release is coherent as a whole.
- [ ] Verify GitHub Pages deployment after merge.
- [ ] Verify `/`, `/pt/`, `/en/`, `robots.txt` and `sitemap.xml` live.
- [ ] Submit/refresh indexing through the relevant webmaster tools after publication.

## Post-launch
- [ ] Add preserved audio/video as it is safely digitized and published.
- [ ] Expand archive nodes progressively rather than delaying the entire hub for perfect historical coverage.
- [ ] Review external profile consistency after the canonical hub is live.
